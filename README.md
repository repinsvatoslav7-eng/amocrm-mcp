# Я Мебель — amoCRM MCP

Полноценный MCP-коннектор к amoCRM API v4 для ChatGPT: чтение, создание, редактирование, задачи, примечания, воронки, поля, связи, теги, вебхуки, каталоги, покупатели, неразобранное и файлы.

## Архитектура

`ChatGPT -> MCP (Render) -> amoCRM API v4`

Долгосрочный токен приватной интеграции хранится только в Environment Variables Render. Он никогда не должен передаваться в чат или попадать в Git.

## Что умеет

Основные группы инструментов:

- диагностика: `amo_health_check`, `amo_get_account`, `amo_audit_tail`;
- универсальный API: `amo_api_get`, `amo_api_post`, `amo_api_patch`, `amo_api_delete`;
- пользователи и события;
- воронки и статусы;
- сделки: список/поиск/карточка/создание/комплексное создание/редактирование/пакетные операции;
- контакты и компании;
- задачи: просмотр/создание/редактирование/закрытие;
- примечания;
- связи сущностей;
- дополнительные поля и группы полей;
- теги;
- вебхуки;
- источники и причины отказа;
- каталоги/элементы;
- покупатели;
- неразобранное;
- файлы: просмотр, загрузка через официальный chunked API, привязка, удаление и восстановление.

Универсальные `amo_api_*` закрывают новые или редкие API v4 endpoints, для которых нет отдельной удобной функции.

## Защита записи

`WRITE_ENABLED=true` разрешает обычную запись: создание/редактирование сущностей, задач, заметок и т. п.

Удаление и другие разрушительные действия требуют одновременно:

1. `DANGEROUS_WRITE_ENABLED=true` в Render;
2. аргумент `confirm=true` в конкретном вызове инструмента.

По умолчанию `DANGEROUS_WRITE_ENABLED=false`.

## 1. Создать приватную интеграцию amoCRM

После одобрения заявления amoCRM:

1. amoMarket -> Создать интеграцию -> Приватная интеграция.
2. Название: `Я Мебель — ChatGPT MCP`.
3. Включить доступ к данным CRM.
4. Включить доступ к файлам.
5. Если нужен инструмент удаления файлов — включить также право удаления файлов.
6. Создать долгосрочный токен приватной интеграции.
7. Токен не пересылать в ChatGPT.

## 2. Развернуть на Render

Создать новый Web Service из репозитория с этими файлами либо использовать `render.yaml`.

Environment Variables:

- `AMOCRM_BASE_URL` — `https://<поддомен>.amocrm.ru`;
- `AMOCRM_ACCESS_TOKEN` — долгосрочный токен;
- `MCP_SECRET` — длинная случайная строка;
- `WRITE_ENABLED=true`;
- `DANGEROUS_WRITE_ENABLED=false` на первом этапе.

Случайный MCP secret можно создать локально:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Start command уже указан в `render.yaml`:

```bash
uvicorn server:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips="*"
```

## 3. Проверка Render

После deploy открыть:

`https://<render-service>.onrender.com/health`

Ожидается JSON с `ok: true`.

MCP endpoint:

`https://<render-service>.onrender.com/mcp`

Он защищён `MCP_SECRET`. Клиент должен передавать один из заголовков:

`Authorization: Bearer <MCP_SECRET>`

или

`X-MCP-Secret: <MCP_SECRET>`

## 4. Подключение к ChatGPT

При добавлении MCP/коннектора указывается URL `/mcp` и Bearer secret. После подключения первым вызовом выполнить `amo_health_check`.

Затем проверить без записи:

1. `amo_list_pipelines`
2. `amo_list_custom_fields(entity_type="leads")`
3. `amo_list_leads(limit=10)`
4. открыть один реальный дубль через `amo_get_lead`
5. найти связанный контакт и проверить `metrika_client_id`, `yclid`, UTM и ID Bitrix.

Только после чтения выполнить небольшой безопасный write-тест — например, добавить тестовое примечание в выбранную тестовую сделку, а затем проверить историю.

## Настройка сквозной аналитики после подключения

Цель проверки — убедиться, что два amo-лида одной заявки получают одинаковую атрибуцию:

- `metrika_client_id`
- `yclid`
- `utm_source`
- `utm_medium`
- `utm_campaign`
- `utm_content`
- `utm_term`
- исходный ID Bitrix

Первый amo-лид — технический дубль заявки. Второй — рабочий квалифицированный лид. Продажные события и деньги должны считаться по второму лиду, а первый использоваться для контроля входящей заявки.

## Важное

- Не коммить `.env` и токены.
- Не включать `ALLOW_INSECURE_MCP=true` на Render.
- Не включать `DANGEROUS_WRITE_ENABLED=true`, пока не проверены чтение и обычная запись.
- API клиент ограничивает скорость до 6 запросов/сек. и делает retry на 429/5xx.
- `/health` публичный и не содержит секретов или CRM-данных.
